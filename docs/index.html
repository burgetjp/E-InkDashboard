E-Ink Dashboard — Architecture Docs

E-Ink Dashboard

FastAPI + Pillow dashboard image server — architecture reference

Platform
Python 3.12 · FastAPI · Pillow · APScheduler · Docker
Entry Point
app/main.py — FastAPI lifespan triggers initial refresh_dashboard() then starts APScheduler
Displays
Joe 800×480 (dark, weather left · quote right) · Sam 600×400 (dark, quote left · weather right)
Data Sources
NOAA Weather API · ZenQuotes · Basmilius SVG icons (rasterized each refresh)

Key Design Principles

  • • In-memory cache only — PNG bytes stored in DashboardCache; no disk I/O on GET /dashboard/*.png requests.
  • • Hourly refresh at :00 — APScheduler CronTrigger(minute=0) fetches weather + quote + icons, renders both PNGs, stores in cache. Also runs immediately on startup.
  • • Pi-side scripts unchanged — dailyEink.py and dailyClear.py unmodified. Only dailyDash.sh changed: a single curl replaces the old Firefox screenshot pipeline.
  • • Failure isolation — if NOAA or ZenQuotes fails at refresh, the previous cached PNG is kept and status flags are updated. On first-boot failure, a plain fallback "Dashboard starting…" PNG is served.
  • • Dark palette, native e-ink colors — black background with condition-matched accent colors drawn from the Inky Impression 7-color native palette to avoid dithering artifacts.

Request Flow

sequenceDiagram participant Pi as Raspberry Pi participant App as FastAPI (app/main.py) participant C as DashboardCache Pi->>App: GET /dashboard/joe.png App->>C: cache.get_joe() C-->>App: PNG bytes (or fallback 800x480) App-->>Pi: 200 image/png

No computation on request — the cache always has bytes ready. Fallback PNG served only on first boot before the initial refresh completes.

Refresh Cycle

graph LR trigger["CronTrigger(minute=0)\nor app startup"] trigger --> icons["load_all_icons(size=120)\nfetch + rasterize all SVGs"] trigger --> weather["fetch_weather(noaa_grid)"] trigger --> quote["fetch_quote()"] icons --> render weather --> render quote --> render render["render_joe(weather, quote, icons) → bytes\nrender_sam(weather, quote, icons) → bytes"] render --> store["cache.store(joe, sam,\nnoaa_ok, quotes_ok)"] weather -->|"raises"| fail["noaa_ok=False\nkeep previous PNG"] quote -->|"raises"| fail2["quotes_ok=False\nkeep previous PNG"]

Icons are re-fetched on every refresh. If either API fails, the previous cached PNG is preserved.

app/weather.py

NOAA Weather API client. Raises httpx.HTTPStatusError on non-2xx — the scheduler catches this and keeps the previous cache.

SymbolDescription
WeatherDataDataclass: period_name, temperature, short_forecast, detailed_forecast, precip_percent.
fetch_weather(grid: str)Async. Fetches https://api.weather.gov/gridpoints/{grid}/forecast. Returns WeatherData from periods[0]. Raises HTTPStatusError on failure.

app/quotes.py

ZenQuotes API client. Same error contract as the weather client.

SymbolDescription
QuoteDataDataclass: text, author.
fetch_quote()Async. Fetches https://zenquotes.io/api/random. Returns QuoteData. Raises HTTPStatusError on failure.

app/icons.py

Weather icon mapping and SVG rasterization. Multi-word keywords must precede their single-word components in ICON_MAPPING — first-match-wins means "mostly sunny" must appear before "sunny".

SymbolDescription
ICON_MAPPINGlist[tuple[list[str], str, str]] — 18 condition groups of (keywords, day_icon_name, night_icon_name).
select_icon_name(short_forecast, period_name)Case-insensitive substring match. Night if period_name.lower() is "tonight" or "overnight". Fallback: "clear-day" / "clear-night".
rasterize_svg(name, size)Synchronous. Fetches {BASE_URL}{name}.svg via httpx.Client, converts via cairosvg.svg2png(), returns RGBA Image.
load_all_icons(size=120)Synchronous. Rasterizes every unique icon name in ICON_MAPPING. On per-icon failure: gray placeholder. Returns dict[str, Image].

app/accent.py

Condition-to-color mapping for dark mode. Same first-match-wins pattern as icons.py. Colors drawn from the Inky Impression 7-color native palette to avoid dithering.

SymbolDescription
select_accent(short_forecast: str)Returns (temp_color, icon_bg_color) as hex strings. Fallback: ("#ffe900", "#ffe900").

app/draw_utils.py

Shared Pillow text utility used by both renderers.

SymbolDescription
wrap_text(draw, text, font, max_width)Splits text into list[str] where each line fits within max_width px via draw.textlength(). A word wider than max_width appears alone on its line.

app/render_joe.py

800×480 dark-mode renderer for Joe's Pimoroni Inky Impression display. Calls select_accent() and select_icon_name() internally.

SymbolDescription
render_joe(weather, quote, icons)Returns bytes (PNG). Layout: header bar (title left, date right) → vertical divider → weather panel left (icon circle + 80px temp + subtitle + forecast box) · quote panel right (label + wrapped quote + right-aligned author).

app/render_sam.py

600×400 dark-mode renderer for Sam's display. Same color constants and font helper as render_joe.py, mirrored layout.

SymbolDescription
render_sam(weather, quote, icons)Returns bytes (PNG). Layout: header bar → vertical divider → quote panel left · weather panel right (icon circle + 52px temp + condition + forecast box).

app/scheduler.py

APScheduler setup and the refresh coroutine. The module-level scheduler is started in main.py's lifespan and shut down on exit.

SymbolDescription
schedulerModule-level AsyncIOScheduler instance.
refresh_dashboard(cache, noaa_grid)Async. Calls load_all_icons(), then fetch_weather() and fetch_quote(). If either raises, updates status flags and returns without touching cached PNGs. On success: render_joe() + render_sam() + cache.store().
start_scheduler(noaa_grid)Adds refresh_dashboard as a CronTrigger(minute=0) job and calls scheduler.start().

API Endpoints

The FastAPI server exposes three endpoints on port 8000.

MethodPathResponse TypeNotes
GET/dashboard/joe.pngimage/png 800×480 Joe profile. Returns cached bytes; no render on request.
GET/dashboard/sam.pngimage/png 600×400 Sam profile. Returns cached bytes; no render on request.
GET/healthapplication/json Last refresh timestamp and per-API status flags.

/health Response

{
  "last_refresh": "2026-05-21T07:00:03.142857",  // ISO-8601, or null on first boot
  "noaa_ok": true,                                // false if last NOAA fetch raised
  "quotes_ok": true                               // false if last ZenQuotes fetch raised
}

last_refresh is set by cache.store() via datetime.now(). A failed refresh that keeps the previous cache does not update last_refresh.

Error Behavior

ScenarioBehavior
NOAA down at refreshKeep previous PNGs. Set noaa_ok = False. Log warning.
ZenQuotes down at refreshKeep previous PNGs. Set quotes_ok = False. Log warning.
Both APIs down on first bootget_joe() / get_sam() return a plain "Dashboard starting…" fallback PNG.
Pi curl failsdailyDash.sh exits early; display is not cleared or updated.

Data Sources

All three data sources are fetched on every hourly refresh.

NOAA Weather API

Endpointhttps://api.weather.gov/gridpoints/{NOAA_GRID}/forecast
Default gridPSR/166,61 (Phoenix, AZ area)
Fields usedperiods[0].name, .temperature, .shortForecast, .detailedForecast, .probabilityOfPrecipitation.value
AuthNone — public API. User-Agent: InkyDashboard/1.0 header sent per NOAA requirements.
On failureRaises httpx.HTTPStatusError. Scheduler catches, keeps previous cache, sets cache.noaa_ok = False.

ZenQuotes

Endpointhttps://zenquotes.io/api/random
Fields used[0].q (quote text) · [0].a (author)
AuthNone — free unauthenticated tier.
On failureRaises httpx.HTTPStatusError. Scheduler catches, keeps previous cache, sets cache.quotes_ok = False.

Basmilius Weather Icons

Open-source SVG icon set (MIT license). Fetched from GitHub raw content and rasterized via cairosvg to RGBA PNG at 120 px. On per-icon failure, a gray placeholder is used — the refresh continues.

Base URLhttps://raw.githubusercontent.com/basmilius/weather-icons/dev/production/fill/svg/
Fetch timingEvery refresh via load_all_icons(size=120) — synchronous, blocks the event loop during startup.
On failurePer-icon gray 120×120 RGBA placeholder. Does not abort the refresh.

Configuration

Environment Variables

Defined in app/config.py via pydantic-settings. Values can be set via environment variables or an optional .env file in the project root. The module-level settings singleton is imported by main.py and scheduler.py.

VariableDefaultPurpose
PORT8000uvicorn listen port
NOAA_GRIDPSR/166,61NOAA gridpoint identifier for Phoenix area weather forecasts
REFRESH_HOUR_INTERVAL1APScheduler interval in hours between dashboard refreshes

Python Environment

Always use venv/bin/python (Python 3.12 via Homebrew). The system Python 3.9 cannot load cairosvg because cairocffi cannot find libcairo on macOS without the venv.

# Activate the project venv
source eink-dashboard/venv/bin/activate

# Or call directly
eink-dashboard/venv/bin/python -m pytest tests/
eink-dashboard/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000

Fonts

Inter Regular and Bold are bundled at assets/fonts/. No external font fetches at runtime — both renderers load from that directory via os.path relative to their module.

FileUsed for
assets/fonts/Inter-Regular.ttfBody text, labels, forecast, author attribution
assets/fonts/Inter-Bold.ttfSection labels, temperature display, header title

Synology Deployment

The synology/ directory inside eink-dashboard/ contains a parallel copy of the app tuned for the Synology NAS environment. Environment variables (NOAA_GRID, PORT) are set directly in its docker-compose.yml. No .env file is needed on the NAS.

Deployment

Quick Reference

# Run tests
eink-dashboard/venv/bin/pytest eink-dashboard/tests/

# Start server locally
eink-dashboard/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000

# Build and run in Docker (from eink-dashboard/)
docker compose up --build

Local Development

Working directory for all commands is eink-dashboard/. The server starts, runs the initial refresh (fetching weather, quote, and all icons), then listens on port 8000. PNG endpoints are immediately available after the lifespan startup completes.

Synology NAS (Production)

The eink-dashboard/synology/ directory contains a parallel copy of the app. Deploy via Docker Compose on the NAS:

# On Synology (SSH in, navigate to synology/)
docker compose up -d --build
  • Port 8000 mapped to host
  • NAS local IP: 10.0.10.123
  • Env vars (NOAA_GRID, REFRESH_HOUR_INTERVAL) set in synology/docker-compose.yml

Raspberry Pi Setup

Cron runs dailyDash.sh at :30 each hour. The script fetches the PNG from the NAS and pushes it to the e-ink display:

#!/bin/bash
SERVER="http://10.0.10.123:8000"
PROFILE="joe"           # change to "sam" for Sam's display
TMP_PNG="/tmp/dashboard.png"

curl -sf --retry 3 --retry-delay 5 --max-time 30 \
  "${SERVER}/dashboard/${PROFILE}.png" > "${TMP_PNG}" || exit 1
/home/red/Dev/scripts/dailyClear.py
/home/red/Dev/scripts/dailyEink.py "${TMP_PNG}"
rm -f "${TMP_PNG}"

dailyClear.py and dailyEink.py are existing Pi-side scripts — unchanged from the old pipeline. killFirefox.sh is no longer needed (artifact of the old Node.js screenshot approach).
